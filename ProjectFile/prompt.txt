# Agent Implementation Prompts (`prompt.txt`)

Use these curated prompts to guide step-by-step implementation, testing, and expansion across the codebase:

---

### 🔹 Prompt 1: Backend Auth & User Schema Implementation
```
Task: Implement User Authentication and JWT Security in Server/server.js.
Requirements:
1. Install bcryptjs and jsonwebtoken in Server/package.json.
2. In Server/server.js, define the User schema with fields:
   - username, email, password (bcrypt), role ('admin' | 'manager' | 'moderator' | 'user'), assignedDevices, status, createdAt.
3. Implement POST /api/auth/signup, POST /api/auth/login, and GET /api/auth/me.
4. Create authenticateToken and requireAdmin middlewares.
5. Ensure all existing hardware Socket.IO connections (esp32_register, esp32_telemetry) continue working without interruption.
```

Task: Implement Add, Edit, and Scoped Listing for ESP32 devices in Server/server.js.

1. Update GET /api/devices with role-based filtering.

### 🔹 Prompt 3: Targeted Broadcast & Anonymous Caller ID (#31#)
```
Task: Implement Targeted Outbound Calling and Anonymous Cloaked Calling in Calls Page and Dispatcher.
Requirements:
1. In the Broadcast Modal, provide routing options:
   - Auto-Balance Across Cluster
   - Specific Physical Hardware MAC (from devices list)
   - Specific Virtual Device ID (from virtualDevices list)
2. Add an Anonymous / Cloaked Caller ID toggle:
   - When checked, enforce GSM private CLI flag (#31# prefix) in dial sequence (ATD#31#017XXXXXXXX;).
   - Generate or accept a custom cloak identifier (e.g. ANON-CLOAK-8812) to mask agent identity in logs.
3. Support recipient input with optional contact names (+88017XXXXXXXX, Name).
```

### 🔹 Prompt 4: Virtual Device Dedicated Addresses & Talk Time Tracking
```
Task: Implement Dedicated Virtual Addresses and Talk Duration Tracking for Virtual Devices.
Requirements:
1. Ensure each VirtualDevice model possesses:
   - virtualMac (unique virtual address, e.g. V-MAC:FF:EE:DD:01, VIR:VIP:02).
   - totalCallDurationSeconds (cumulative seconds of talk time).
   - lastCallDurationSeconds (duration of most recent call).
   - totalCallCount and totalSmsCount.
2. On the Virtual Devices page (/devices/virtual):
   - Display formatted talk time (e.g. "3m 20s") on each card.
   - Provide a 1-click address copy button.
   - Provide a direct "Test Call" button with a modal pre-filled with this virtual address.
3. Whenever a call routed through a virtual ID terminates, automatically update its totalCallDurationSeconds.
```

### 🔹 Prompt 5: Telco Carrier Signaling & Accurate Feedback States
```
Task: Implement Accurate Carrier Feedback Detection for all Voice Calls.
Requirements:
1. Parse SIM800L unsolicited response codes and telco signaling into distinct states:
   - 'success': Answered and audio prompt played.
   - 'rejected': User Determined User Busy (UDUB / Release Cause 17).
   - 'call_waiting': Call Waiting (CW) active on recipient line.
   - 'forwarded': Diverted to voicemail or forward number.
   - 'busy': Line engaged.
   - 'unreachable' / 'number_off': Switched off or out of coverage.
2. Render distinct color badges for each carrier state in the calls table.
3. Add a "Details" inspector modal displaying exact minutes/seconds, retry count, audio track, requester identity, and raw AT command trace.
```

---

### 🔹 Prompt 6: Zero-Drop Priority FIFO Queue under High Load
```
Task: Implement a Resilient Priority Queue Buffer to Prevent Request Failure under Heavy Server/Modem Load.
Requirements:
1. When all modems are busy or system concurrency is maxed out, place new requests into a FIFO buffer with status: 'queued' and an assigned queuePosition.
2. As modems become idle, automatically dequeue the oldest request.
3. If a call returns busy or call waiting, automatically retry with backoff up to 3 times before final marking.
4. Display active queue position and zero-drop status in the UI.
```
