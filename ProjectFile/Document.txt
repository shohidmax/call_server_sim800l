## 3. REST API Specifications

### 3.1 Authentication Endpoints (`/api/auth`)
- `POST /api/auth/signup`
  - **Payload**: `{ "username": "sarwar", "email": "admin@sim800l.local", "password": "...", "role": "admin" }`
  - **Response**: `{ "success": true, "token": "jwt...", "user": { ... } }`
- `POST /api/auth/login`
  - **Payload**: `{ "email": "admin@sim800l.local", "password": "..." }`
  - **Response**: `{ "success": true, "token": "jwt...", "user": { ... } }`
- `GET /api/auth/me`
  - **Headers**: `Authorization: Bearer <jwt_token>`
  - **Response**: Current authenticated user profile with assigned hardware permissions.

### 3.2 Device & Fleet Endpoints (`/api/devices`)
- `GET /api/devices`: List all registered physical modems (admin sees all; users see assigned).
- `POST /api/devices`: Register new hardware MAC with name, group, and allowed users.
- `PUT /api/devices/:mac`: Edit hardware profile metadata.
- `DELETE /api/devices/:mac`: Unbind/delete hardware profile.
- `GET /api/devices/:mac/events`: Detailed activity audit trail of who made changes, dispatched calls, or edited settings.

### 3.3 Call Dispatch, Routing & Queue Endpoints (`/api/broadcast`, `/api/jobs`)
- `POST /api/broadcast`:
  - **Payload**:
    ```json
    {
      "phone_call_list": ["+8801711111111", "+8801722222222"],
      "mac": "44:1D:64:BD:22:EC",         // Optional specific hardware MAC
      "virtualId": "VIR:CLUST:01",         // Optional specific virtual gateway
      "isAnonymous": true,                 // Optional #31# private CLI cloak
      "anonymousId": "ANON-CLOAK-8812",    // Optional cloak identifier
      "audio": "0001",                     // DFPlayer Mini audio track number
      "recipientNames": { "+8801711111111": "Sakib" }
    }
    ```
- `GET /api/jobs`: Filterable call jobs list by date range, route, status, and requester.
- `GET /api/jobs/report`: Generates aggregated performance report (total talk minutes, answer rate %, carrier feedback breakdown).

### 3.4 SMS Messaging (`/api/sms`)
- `GET /api/sms`: Fetch inbound/outbound SMS with search and device filtering.
- `POST /api/sms`: Send outbound SMS or receive inbound webhook from SIM800L.

## 4. Socket.IO Real-Time Event Protocol

### 4.1 Client Commands
| Event | Direction | Payload | Description |
| :--- | :--- | :--- | :--- |
| `dashboard_cmd_dial` | Client -> Server | `{ mac, phone, audio, isAnonymous }` | Direct manual voice dial with optional #31# |
| `dashboard_cmd_hangup` | Client -> Server | `{ mac }` | Terminates active call immediately |
| `dashboard_cmd_ussd` | Client -> Server | `{ mac, code }` | Executes USSD balance inquiry (e.g. `*566#`) |
| `dashboard_send_sms` | Client -> Server | `{ mac, phone, message }` | Dispatches outbound SMS via SIM800L |
| `dashboard_cmd_reboot` | Client -> Server | `{ mac }` | Initiates hardware MCU reset |
| `dashboard_cmd_flightmode` | Client -> Server | `{ mac, state }` | Toggles SIM800L airplane mode (`AT+CFUN`) |

### 4.2 Hardware Socket Communication (ESP32 <-> Server)
- **`esp32_register`**: Sent on hardware boot with `{ "mac": "44:1D:64:BD:22:EC", "ip": "192.168.1.105" }`.
- **`esp32_telemetry`**: Emitted every 10s with `{ mac, wifi_rssi, sim_signal, sim_operator, sim_number, is_calling }`.
- **`execute_call`**: Server directs ESP32 to dial `{ job_id, phone_to_call, audio }`.
- **`call_result`**: ESP32 reports execution outcome `{ job_id, status: 'success' | 'busy' | 'rejected' | 'call_waiting' | 'forwarded' | 'unreachable', duration_seconds: 45 }`.

## 5. Carrier Signaling Feedback Standards
The system parses native SIM800L unsolicited response codes and call progress indicators into accurate telco states:
1. **`success` / `received`**: Call answered, audio prompt played, exact talk duration recorded.
2. **`rejected` (UDUB)**: User Determined User Busy (Release Cause 17) — actively declined on subscriber handset.
3. **`call_waiting` (CW)**: Subscriber handset is on another call with Call Waiting active.
4. **`forwarded`**: Diverted to voicemail or carrier auto-divert system.
5. **`busy`**: Network engaged / busy tone.
6. **`unreachable` / `number_off`**: Subscriber terminal switched off or out of coverage.

## 6. Zero-Drop Priority FIFO Queue Architecture
Under high channel or server load:
- Calls exceeding immediate modem concurrency are queued in persistent FIFO order (`status: 'queued'`) with an assigned `queuePosition`.
- As physical or virtual channels become idle, the queue processor pops the oldest job.
- If a dialed call encounters carrier busy or waiting, an exponential backoff auto-retry worker reschedules it up to 3 attempts, guaranteeing **Zero Request Loss**.

## 8. Role-Based Access Control (RBAC) Matrix
1. **Admin (Root)**: Full unconstrained CRUD access to all devices, virtual gateways, call records, SMS, campaigns, user management, and security audit logs.
2. **Manager**: Full access to dialer, broadcast queue, campaigns, modem groups, and reports. Cannot modify user accounts or wipe security audit logs.
3. **Moderator**: Access to manual dialing, SMS replies, and feedback ticketing. Cannot modify system groupings or delete hardware modems.
4. **Viewer**: Read-only monitoring of fleet telemetry, call queue status, and performance metrics. Cannot initiate calls or delete records.
